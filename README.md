# GoatShot

GoatShot is a Windows-native screenshot and screen recording application prototype based on `spec.md`.

This first build intentionally targets Milestone 0 / early Milestone 1:

- WPF desktop app, no web server or Docker dependency.
- Tray process with capture and workspace actions, plus app-owned tray menu preview proof for audits.
- Global hotkey registration for the spec defaults where Windows allows it.
- Region, fullscreen, all-monitors, active monitor, active window, vertical/horizontal scrolling active-window, fixed-size preset, last-region, and explicit delayed screenshot capture.
- Frozen-screen region selection overlay with edge snapping, a window/monitor chooser, pixel lens, and configurable capture-context padding.
- Optional Android ADB screenshot import through CLI diagnostics and `adb exec-out screencap -p`, bounded `adb shell screenrecord` pull/import for short MP4s, live-preview dry-run planning for repeated screencap polling or experimental H.264 stream plans, and a guarded `capture android-preview --execute` path for explicitly confirmed, selected-device, bounded screencap polling or bounded raw H.264 stdout capture with manifest/review output. H.264 preview execution writes a raw `.h264` stream and optionally remuxes to MP4 when FFmpeg is available. The V1 decision is to keep Android support bounded to these helpers; production Android live streaming, scrcpy-style mirroring, and Android companion-app streaming are post-V1 scope.
- Optional browser extension contract/prototype plus native CLI receiver, native messaging host registration, local ZIP packaging, popup/options UX, install-guide, read-only install-plan generation, temporary install-assist generation, read-only publication-plan generation, read-only publication evidence recording, read-only enterprise policy template planning, live-proof manifest/validation, store-readiness checklist/copy generation, local store submission package generation, operator diagnostic codes, bounded stitch-manifest planning, browser-download stitch-package export, and bounded local stitch-package import for consented page geometry, selected-element geometry, DOM metadata, bounded console/network telemetry summaries, redacted handoff payloads, optional screenshot import, and local stitched bitmap import. Edge live safe-fixture load/export/import proof is saved under `artifacts/tranche-browser-live-fixture-proof-closure/`; actual browser-store account submission/review/signing/availability, permanent or store-managed automatic extension installation, enterprise policy deployment/force-install proof, and Chrome/Firefox live fixture proof remain later/manual scope.
- Virtual printer/file-drop import contract for PDF/image print outputs, with CLI `print-import setup` / `print-import contract` / `print-import diagnostics` / `print-import import`, watched-folder import support, setup-note generation, driver-feasibility diagnostics, and explicit driver-install boundary.
- Local Plugin SDK manifest discovery for app-owned local plugins, disabled-by-default trust state, reviewed activation metadata writes, allowlisted dry-run actions, guarded local action execution with timeout/redacted output, diagnostics, sample no-network fixtures, remote plugin registry/package staging with optional RSA SHA-256 package signature verification, operator-facing update summaries, governed background check/stage-only runs, Task Scheduler handoff generation, explicit Task Scheduler status/register/unregister lifecycle commands, and guarded staged-package installation into the active local plugin folder without trusting, enabling, allowlisting, installing, or executing plugin code automatically.
- Read-only companion portal export through `companion-portal export`, which writes local static JSON/HTML summaries of policy, diagnostics, share-history aggregates, manual-validation status, and release-proof metadata without syncing, uploading, attaching media, reading secrets, mutating policy, or contacting a portal service; `companion-portal media-review` and opt-in `--media ... --accept-media-copy` export/serve flags add local static review pages for explicitly selected media only, and `companion-portal serve` can host the sanitized report plus allowlisted media-review files on loopback by default or as an explicitly accepted self-hosted shared-token read-only preview with no write routes.
- Short GIF recording with desktop/tray active-monitor pause-resume and CLI all-monitor/monitor/window/region/fixed-region targets, plus optional native/FFmpeg-backed MP4 recording from the desktop app or CLI with configurable recording overlay placement/style.

Image combine/split/stitch utilities are implemented locally. The desktop workspace supports multi-select `Combine selected` for image captures, and the CLI supports `image combine`, overlap-aware `image stitch`, plus grid-based `image split`.

Sensitive text detection is implemented for text the user provides or GoatShot recognizes through OCR. It detects email addresses, phone numbers, IP addresses, credit-card-like values with Luhn validation, API key/password assignments, bearer tokens, JWTs, AWS keys, GitHub tokens, connection strings, and URLs containing token-like query parameters. When desktop OCR finds sensitive text, GoatShot copies the redacted text instead of the raw text. The selected-capture `Redact OCR secrets` action and CLI `redact-ocr` command use OCR word boxes to draw flattened redaction blocks into a new PNG copy.

QR/barcode decode is implemented locally with ZXing.Net. In the desktop app, select a capture and use `Decode QR/barcode`; GoatShot copies the first decoded value to the clipboard and asks before opening an HTTP(S) URL. The CLI supports `qr decode` for images and `qr generate` for QR PNG creation.

Workspace metadata search is backed by a local SQLite FTS5 sidecar database. The JSON workspace index is still retained as a compatibility source, while the desktop search box and CLI `search` command use the SQLite index for filenames, capture kind, source app, notes, paths, and stored OCR/plain text. Search snippets are passed through sensitive-text redaction before display.

Local OCR is implemented through `Windows.Media.Ocr`. It recognizes text from image files and selected captures, stores recognized text plus word bounding boxes in the workspace item, and updates the SQLite search index. A blank OCR language setting uses the current Windows user profile languages; otherwise use a tag such as `en-US`. This fallback does not expose confidence scores, so OCR confidence remains pending until a Windows AI Text Recognition adapter is added for NPU-capable devices.

OCR visual redaction is implemented as a destructive export-copy workflow: GoatShot detects sensitive spans in stored OCR text, maps those spans to OCR word bounds, applies solid, pixelate, or blur effects over the source image, and saves a flattened PNG. Solid redaction remains the safe default.

Gemini image editing, screenshot explanation, and explicit transcript-based video drafting have real provider plumbing now, but they still require a user-supplied Gemini API key and live API access. API keys are stored with Windows DPAPI for the current user and are not written to settings JSON. The built-in image-model manifest is based on the current Google AI image-generation docs as of 2026-06-12 and includes `gemini-3.1-flash-image`, `gemini-3-pro-image`, and `gemini-2.5-flash-image`; users can override the manifest/model ID in Settings. AI model capability display is available from Settings validation and CLI `ai-models`. AI explanations are copied to the clipboard and saved as redacted local notes when run from the workspace. AI edit/analyze/video-draft attempts are recorded in a local redacted action history without storing image payloads. The desktop AI review window can mark entries accepted, rejected, or iterated, copy previews/prompts, open generated outputs, and browse prompt history. The CLI supports `ai-history accept`, `reject`, `iterate`, `prompts`, and `retry`; retry links the new attempt to the original history entry and can rerun supported image analysis/edit, video-summary, and bug-report draft actions with a different model, prompt, or profile context. The editor can reuse the latest local AI edit prompt.

Watch folders are implemented for the desktop app. They monitor configured folders while GoatShot is running, wait for new files to become readable, copy supported image/video files into the GoatShot library, add them to the workspace index, and can optionally copy images, create metadata-stripped image copies, or run quick share. This is local automation, not a background Windows service yet.

Run-at-startup is implemented through the current user's Windows Run key (`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`). It registers the current GoatShot executable path when enabled in Settings and removes that value when disabled.

Workflow profile import/export is implemented for recording defaults and named recording profiles, including audio gain/noise-gate/mute controls, sharing defaults, provider settings, upload denylists, watch-folder behavior, and automation rules. Exports omit custom script, custom webhook, Slack webhook, Discord webhook, and Microsoft Teams webhook values by default because those fields can contain tokens or private infrastructure. DPAPI credentials are always omitted. CLI exports can include the sensitive non-DPAPI values with `--include-sensitive`, and imports only apply them when the same flag is supplied.

Workflow rules can be evaluated for `CaptureCreated`, `CaptureEdited`, `FileAddedToWatchFolder`, `RecordingCompleted`, `OcrCompleted`, `UploadCompleted`, and `AiActionCompleted`. Conditions cover source app, window title, capture kind, monitor, hotkey/workflow profile, file extension, file size, OCR text, and sensitive-data presence or absence. Desktop global-hotkey captures stamp the capture with the triggering hotkey action name, and CLI captures can set a custom marker with `--profile` / `--hotkey-profile`; the marker is persisted in workspace JSON and the SQLite metadata index. Wired actions include clipboard image/file/path, local export folder save, OCR, OCR-sensitive visual redaction when word bounds exist, parameterized image-effect copies, metadata-stripped copy, default share destination, custom script, custom webhook, Markdown bug-report document export, and status notification. Image-effect automation supports `ImageEffectMode` values `Solid`, `Blur`, or `Pixelate`, plus `ImageEffectRegion` as `full` or `x,y,width,height` percentages. Open-editor is recorded for the desktop shell, and unattended local delete is intentionally not executed. Settings includes a multi-rule workflow manager with saved-rule list, new/duplicate/delete/update controls, trigger, source/window/profile/file/OCR/sensitive-data conditions, capture-kind, monitor, min/max byte, image-effect mode/region controls, and common local/share/document/webhook/script actions; workflow import/export preserves unknown future automation-rule fields where JSON extension data can be retained. After captures, the desktop quick-actions window exposes open, edit, copy, share, AI explain, document export, script/webhook dry-run, and explicit local-delete actions. Rule runs write JSON and Markdown logs with matched/skipped reasons and action outcomes. The CLI exposes `workflows validate`, `workflows list-rules`, `workflows status`, `workflows dry-run`, `workflows dry-run-script`, `workflows dry-run-webhook`, and `workflows run` for profile validation, rule inspection, dry-run planning, and execution.

Workflow starter templates are available in Settings and CLI for common safe automations: capture-to-documentation, OCR sensitive-data redaction, upload-complete notification, recording-to-bug-report, and AI-summary follow-up. Templates create disabled rules by default for review in Settings; CLI `workflows add-template <id> --enable` can opt into enabling immediately. Use `workflows templates [--json]` to list templates and `workflows add-template capture-doc [--replace] [--json]` to add one to the current local settings.

Diagnostic bundles are implemented as local zip files for support and troubleshooting. They include runtime diagnostics, provider-readiness markers, GPU/display/encoder capability probes, recording engine readiness, effective managed-policy state, path reports, redacted settings, workspace metadata summaries, loaded assembly versions, privacy notes, and capped redacted log files when logs exist. Bundles intentionally exclude capture files, thumbnails, full OCR text, AI payloads, secret values, and DPAPI secret files.

Managed policy controls are implemented as local/admin posture foundations. Settings JSON can carry `managedPolicy` flags, a managed environment can point `GOATSHOT_MANAGED_POLICY_PATH` at a JSON policy file, and `goatshot admin-policy` can validate, explain, diff, import, and export `goatshot.admin-policy.v1` bundles without secrets. Deny-wins policy can disable AI provider calls, disable external sharing/upload, disable custom scripts, disable custom webhooks, disable local plugins, restrict plugin ids/actions, restrict allowed share destinations, require private capture mode, disable browser-extension handoff, disable Android capture, disable virtual-printer import, disable diagnostics log capture, and set a retention-days marker. Effective policy state is visible in Settings, `diagnostics print`, provider diagnostics, workflow script/webhook dry-runs, admin-policy explain output, and diagnostic bundles. Policy blocks are enforced in the share facade, Gemini provider path, local plugin dry-run/execution gates, Android capture CLI, browser-extension handoff CLI, and print-import CLI, so CLI/UI callers cannot bypass them by toggling ordinary settings.

Companion portal V0 is intentionally read-only. `goatshot companion-portal export --output <folder> [--manual-validation <folder>] [--proof-root artifacts]` writes `companion-portal-report.json` and `index.html` with effective managed-policy summary, redacted diagnostics snippets, aggregate share/upload history counts, manual-validation status counts, and release-proof manifest metadata. `goatshot companion-portal media-review --output <folder> --media <file> --accept-media-copy` adds `companion-portal-media-review.json`, `media-review.html`, and copied operator-selected media under `media/`; export/serve also accept repeatable `--media <file>` only with `--accept-media-copy`. `goatshot companion-portal serve --output <folder> [--host 127.0.0.1] [--port 0] [--check]` creates the same sanitized report and serves only `/`, `/index.html`, `/companion-portal-report.json`, `/health.json`, and manifest-listed media-review files on loopback by default. `goatshot companion-portal serve --output <folder> --host 0.0.0.0 --self-hosted --accept-remote-clients --auth-token-env <name> [--check]` explicitly opts into a self-hosted shared-token read-only preview; the token must be supplied by env var or CLI, is not serialized into reports, and `--check` sends Bearer auth. Mutating methods return `405`, unauthenticated self-hosted requests return `401`, non-loopback bind requests are rejected unless remote clients and acceptance are both explicit, and weak/missing self-hosted tokens are rejected. Export mode sets explicit false flags for hosting, portal contact, sync, upload, secret access, policy mutation, and plugin execution; media-review mode sets local media attachment/review flags true only for explicitly selected local files. Preview mode keeps mutating routes, account login, sync, upload, secret access, policy mutation, and plugin execution false. Default exports omit capture files, recordings, thumbnails, OCR text, transcripts, prompts, raw logs, diagnostics bundles, provider URLs, credentials, and local file paths; media-review exports omit source paths and include only copied selected files, relative links, hashes, byte counts, and content types. Hosted portal accounts, first-class account login, team sync, hosted/remote media hosting, and remote admin enforcement are not implemented.

Bug report export is implemented for selected workspace items and CLI targets. The exported Markdown, HTML, PDF, or DOCX report includes environment details, capture metadata, attachment path, repro placeholders, and redacted notes/OCR text. It does not upload attachments or call AI.

Transcript and video-intelligence drafts are implemented as local-first document workflows. `transcribe` can convert a provided `--srt` file, sidecar `.srt`, embedded subtitle stream, configured local Whisper CLI result, or opt-in Gemini speech-to-text result into timestamped transcript text. Set `GOATSHOT_WHISPER_EXE` or pass `--whisper-exe` to use a local Whisper executable; `whisper-cli`/whisper.cpp can also use `GOATSHOT_WHISPER_MODEL` or `--whisper-model`. Pass `--ai --provider gemini` to `transcribe` only when the user wants GoatShot to extract short 16 kHz mono WAV audio and send it to the configured Gemini model for speech-to-text; longer recordings still need local Whisper/SRT until a Files API media-upload path is added. `video-intel` uses a provided transcript/SRT or the same transcription path to generate a local title, summary, and chapters document in Markdown, HTML, PDF, or DOCX. Add `--ai` or `--provider gemini` to request an AI-assisted title/summary/chapter draft from redacted transcript text; when provider transcription is needed first, the exported report notes that extracted audio was sent for speech-to-text. The workflow does not upload the original video file itself. `doc-packet` creates a local documentation packet with a redacted manifest and README linking source media, transcript, SRT, video summary, bug report export, keyframes, source metadata, and AI review state. `bug-report` can include transcript/SRT/video-summary/keyframe/context enrichment for recording-derived reports.

Step recorder export is implemented in the desktop app. Start the recorder, click through the target workflow, then stop it to export Markdown and HTML guide files under the local Documents library. Each step captures the active window, stores the screenshot in the workspace, records app/window/click context, and attempts local OCR. This is a screenshot/documentation workflow, not video recording or browser telemetry capture.

## Custom Sharing

Custom scripts run through PowerShell with the configured command after placeholder substitution:

```text
{file}
{metadata}
{ocr}
{id}
{capture_type}
```

Example:

```powershell
& "C:\Tools\my-uploader.ps1" -File "{file}" -Metadata "{metadata}" -CaptureId "{id}"
```

Custom webhook sharing sends `multipart/form-data` with:

- `file`: the capture file
- `metadata`: JSON capture metadata

If script output or webhook response contains a URL, GoatShot copies the first URL to the clipboard.

Slack sharing posts a JSON notification to an incoming webhook URL. It does not upload local files because Slack incoming webhooks do not support file upload; use WebDAV, FTP/FTPS, Discord, or a cloud file provider when the media must leave the machine. Configure the URL and message template in Settings, or pass `--slack-webhook-url` and `--slack-message` from the CLI.

Discord sharing sends `multipart/form-data` to a Discord webhook URL with the capture file plus a message payload. Configure the URL and message template in Settings, or pass `--discord-webhook-url` and `--discord-message` from the CLI.

Microsoft Teams sharing posts an Adaptive Card notification to an incoming webhook URL. It does not upload local files. Configure the URL and message template in Settings, or pass `--teams-webhook-url` and `--teams-message` from the CLI.

S3-compatible sharing uses a path-style signed PUT request with AWS Signature V4. Configure endpoint, bucket, region, key prefix, and optional public base URL in Settings. Access key ID and secret access key are stored with Windows DPAPI for the current user and are not written to settings JSON or workflow profile exports. The CLI can also pass `--s3-endpoint`, `--s3-bucket`, `--s3-region`, `--s3-prefix`, `--s3-public-base-url`, `--s3-access-key`, and `--s3-secret-key`; explicitly provided keys are saved through DPAPI for future uploads.

Imgur sharing uses the v3 image upload endpoint with a user-supplied Client ID. Configure the endpoint and save the Client ID in Settings; the Client ID is stored with Windows DPAPI for the current user and is not written to settings JSON or workflow profile exports. The CLI can pass `--imgur-endpoint` for compatible gateways or local testing and `--imgur-client-id` to save the Client ID through DPAPI before upload.

SFTP sharing shells out to OpenSSH `sftp.exe` in batch mode. Configure host, port, username, remote directory, optional private key path, optional public base URL, and optional executable path in Settings. The upload uses key files, ssh-agent, or whatever account policy OpenSSH can satisfy non-interactively; GoatShot does not store SFTP passwords. Unknown host keys must already be trusted through OpenSSH, otherwise batch upload fails safely. The CLI can pass `--sftp-host`, `--sftp-port`, `--sftp-user`, `--sftp-remote-dir`, `--sftp-key`, `--sftp-public-base-url`, and `--sftp-executable`.

WebDAV sharing uploads with HTTP `PUT` to the configured base URL, remote directory, and generated capture file name. If a username is configured, a password must be saved with Windows DPAPI for the current user; passwords are not written to settings JSON or workflow profile exports. An optional public base URL makes successful uploads copy a share URL. The CLI can pass `--webdav-base-url`, `--webdav-remote-dir`, `--webdav-user`, `--webdav-password`, and `--webdav-public-base-url`.

FTP/FTPS sharing uploads to the configured host, port, remote directory, and generated capture file name. The password is stored with Windows DPAPI for the current user and is not written to settings JSON or workflow profile exports. Enable FTPS explicit TLS with Settings or `--ftps`; an optional public base URL makes successful uploads copy a share URL. The CLI can pass `--ftp-host`, `--ftp-port`, `--ftp-user`, `--ftp-password`, `--ftp-remote-dir`, `--ftp-public-base-url`, and `--ftps`.

Cloudinary sharing uses the REST upload endpoint at `https://api.cloudinary.com/v1_1/<cloud name>/<resource_type>/upload` by default. Unsigned upload requires a cloud name and upload preset. Authenticated upload stores the API key and API secret with Windows DPAPI for the current user and sends them through an HTTP Basic Authorization header; those credentials are not written to settings JSON or workflow profile exports. The CLI can pass `--cloudinary-cloud-name`, `--cloudinary-resource-type`, `--cloudinary-upload-preset`, `--cloudinary-folder`, `--cloudinary-api-base-url`, `--cloudinary-api-key`, and `--cloudinary-api-secret`.

Dropbox sharing uses the Dropbox API v2 content upload endpoint with an OAuth access token stored with Windows DPAPI for the current user. GoatShot uploads to the configured remote folder, then calls the Dropbox API temporary-link endpoint and copies the returned link when available. A configured OAuth client ID can launch browser authorization through a local callback with PKCE and save returned access/refresh tokens; `oauth live-proof-plan` now writes Google Drive-specific scope, consent, account diagnostic, upload-command, and cleanup-boundary guidance, while live Google consent/account proof remains pending. The CLI can pass `--google-drive-folder-id`, `--google-drive-anyone-reader`, `--google-drive-access-token`, `--google-drive-upload-api-base-url`, and `--google-drive-api-base-url`.

## Recording Smoke

```powershell
.\scripts\smoke-recording.ps1 -Targets fixed -DurationSeconds 1 -Fps 5 -NoBuild
```

The recording smoke script runs the CLI against isolated local/library roots, writes recordings plus logs under `artifacts\tranche-recording-smoke`, and validates nonempty output plus video metadata when `ffprobe.exe` is available. The safe default is fixed-region recording. `monitor`, `window`, and `all-monitors` targets capture live desktop content, so they require `-AllowLiveDesktopCapture` after preparing a safe monitor, foreground window, or desktop.

For a private-safe native MP4 smoke that records only an app-owned WPF staging window, run `.\src\GoatShot.App\bin\Release\net10.0-windows10.0.19041.0\GoatShot.exe --record-proof-scene-output .\artifacts\tranche-proof-scene-recording-smoke\proof-scene-recording.mp4 --record-proof-scene-duration 8` after a Release build. The command writes a `.proof.json` sidecar, records explicit proof-scene window bounds with microphone/system-audio/webcam disabled, and is locally proven under `artifacts\tranche-proof-scene-recording-smoke`. It is a bounded app-owned recording smoke, not live multi-monitor, long-run, audio-sync, webcam-permission, or clean-machine proof.

For audio/video confidence, pass `-Audio mic-muted`, `-Audio system-audio-muted`, `-Audio both-muted`, `-Audio mic`, `-Audio system-audio`, or `-Audio both` with `-AllowLiveAudioCapture`. When `ffprobe.exe` is available, the smoke script validates that an audio stream exists and that audio/video stream durations stay within `-MaxAudioVideoDeltaSeconds`.

For proof planning without recording, pass `-PlanOnly`; the script writes `proof-matrix.json` and `proof-matrix.md` describing each target's live-content/audio safety class, required consent switches, and validation coverage. Normal runs also save `diagnostics\record-preflight.json`, `diagnostics\record-devices.json`, `summary.json`, `summary.md`, and `run-manifest.json` with explicit validation booleans for file, metadata, duration, audio stream, and audio/video delta checks. Pass `-RequireFfprobe` when the run must fail instead of falling back to file-length-only validation.

Recording confidence is also surfaced without starting a live capture. `record devices`, `record preflight`, `diagnostics devices`, and `diagnostics recording` report structured ready/warning/blocked states for selected/default microphone, loopback audio, webcam, native WGC/D3D/Media Foundation recording, and FFmpeg fallback, including concrete recovery actions. The WPF recording panel summarizes the current engine confidence inline, while Settings shows device confidence after refreshing recording devices. Live desktop/audio/webcam proof remains an explicit opt-in smoke step.

## Gemini

Gemini setup lives in Settings:

- Enable AI features.
- Save a BYO Gemini API key.
- Validate credentials and list available models.
- Choose the API endpoint and default image model.
- Optionally point to a custom model manifest JSON.

The editor has grouped annotation and privacy tool zones, freehand drawing, spotlight emphasis, a first-viewport active-tool status panel, keyboard tool shortcuts, an AI prompt box, prompt-history reuse, export/print actions, and an `AI edit` button. Redact, Blur, and Pixelate are visually separated from general annotation tools, and the editor can preview stored OCR-sensitive word boxes before applying flattened solid/blur/pixelate redaction copies. Fresh editor proof is saved at `artifacts/tranche-editor-privacy-tools/editor-window.png` and `artifacts/tranche-editor-privacy-tools/editor-accessibility.md`; prior Product Design proof remains at `artifacts/product-design-audit/2026-06-14/10-editor-privacy-tools.png`. When confirmation is enabled, GoatShot asks before sending the current screenshot and prompt to Gemini. Edited images are saved under the local app data AI output folder and imported into the workspace.

## Automation

Watch folders and automation rules are configured in Settings:

- Enable watch folders while GoatShot is running.
- Add one watched folder per line.
- Auto-import images/videos from watched folders.
- Optionally include subdirectories.
- Optionally copy imported images, strip metadata, or quick-share after import.
- Configure capture-created rules in Settings and import/export fuller rule sets through workflow profiles or CLI.

For isolated testing or portable-style runs, these environment variables override the default data roots:

```powershell
$env:GOATSHOT_LOCAL_ROOT = "C:\Temp\GoatShotLocal"
$env:GOATSHOT_LIBRARY_ROOT = "C:\Temp\GoatShotLibrary"
```

## Storage

Default local app data:

```text
%LOCALAPPDATA%\GoatShot\
```

Default capture library:

```text
%USERPROFILE%\Pictures\GoatShot\
```

Private capture mode saves temporary files but does not add them to the persistent workspace index.
