# GoatShot V1 Readiness Summary

> [!IMPORTANT]
> **Historical document:** This report preserves GoatShot `0.2.0`-era readiness evidence and is no longer the current product status. See the [Receipts 0.3.0 Readiness Summary](receipts-0.3.0-readiness-summary.md) for the active release-candidate assessment.

Date: 2026-08-10

Purpose: summarize what is implemented, what is locally proven, what remains manual, what is parked for OAuth/live accounts, and what belongs to later modules.

## Current Readiness

GoatShot Personal V1 `0.2.0` now has a self-installing, unsigned, self-contained single-EXE release path with per-user startup, single-instance activation, atomic update/rollback, repair/uninstall controls, embedded runtime extraction, bundled LGPL FFmpeg, bundled ONNX person segmentation, SSH.NET SFTP, optional external Whisper, explicit-consent Gemini speech-to-text, release metadata, SBOM/notices, and pinned GitHub verification/release workflows.

The GitHub `v0.2.0` publication is a prerelease, not a stable-readiness claim. The in-process Windows USB/ADB transport is implemented and deterministically tested, but clean-profile Windows Sandbox, sign-out/sign-in tray startup, dual-monitor/long-recording/audio/webcam/accessibility, and authorized Android hardware observations have not been recorded for this revision. OAuth remains parked by scope.

Entries below that mention `0.1.x` portable ZIPs, a shipped `GoatShot.Cli.exe`, external-only segmentation, or Inno Setup are retained as historical evidence only. The `0.2.0` single-EXE posture above supersedes those packaging claims.

## OAuth And Live Account Work Parked

OAuth live-proof plan generation is locally proven under `artifacts/tranche-oauth-live-proof-plan/`, with provider-specific Google Drive, Google Photos, OneDrive, Dropbox, YouTube, and OneNote proof-plan polish proven under `artifacts/tranche-oauth-provider-specific-proof-plan/` and the current focused source/test lane: `goatshot oauth live-proof-plan` reads configured OAuth providers and writes Markdown/JSON operator evidence instructions with provider kind, scope review, consent checklist, account diagnostics, provider-specific upload command hints, cleanup boundaries, and false mutation flags for opening browsers, contacting providers, exchanging codes, storing tokens, refreshing tokens, uploading files, and deleting remote files. It is a plan only.

OAuth live-evidence recording is locally proven under `artifacts/tranche-oauth-live-evidence-recorder/`: `goatshot oauth record-live-evidence` records reviewed evidence references for configured providers, rejects a `passed` record unless consent, exchange, refresh, upload, cleanup, and account evidence categories are present, and writes Markdown/JSON records without opening a browser, contacting providers, exchanging codes, storing tokens, refreshing tokens, uploading files, or deleting remote files. It is a recording helper only; the actual real-account proof still requires an operator-owned live run.

By current direction, live account proof can stay parked for now. Do not block non-OAuth buildout on:

- Google Drive live OAuth consent screen proof.
- Google Photos live OAuth consent screen proof.
- Dropbox live OAuth consent screen proof.
- OneDrive live OAuth consent screen proof.
- Refresh-token persistence and expiry recovery against live accounts.
- Live cloud upload proof and live-account remote-delete behavior.

Current Google Drive, Google Photos, Dropbox, YouTube, OneNote, and OneDrive behavior should keep reporting local/fake/token proof honestly and should not be described as live consent-proven.
